# 仕事のモデル

Agent Projectは、画面ではなく、仕事のモデルを中心に作られています。このモデルがあるので、エージェントは、次に何をするか、いつ終わりか、いつあなたに聞くか、何を残すかを判断できます。カンバン、`agpj`コマンド、ファイルは、どれも同じモデルへの入口です。操作に慣れたら、一度このページを読んでください。ほかのページの説明は、ここで扱う考え方に沿っています。

## 要素

| 要素 | 内容 | エージェントにとっての役割 |
| --- | --- | --- |
| **プロジェクト** | 作業フォルダに結びつく作業の単位で、エピック・タスク・質問・履歴を持ちます。 | 作業の範囲を一つに定めます。プロジェクトが見つからないときは、推測せずに止まって知らせます。 |
| **エピック** | 目的と、タスクの進行順。 | どのタスクから進めるかの順序になります。 |
| **タスク** | 単独でレビューできる一つの作業。担当は**AI**か**ユーザー**で、作成時に決まり、変えられません。 | 一度に進めてレビューする単位と、担当を示します。 |
| **完了条件** | 各タスクにあり、何を満たせば終わりかを示すチェックリスト。 | 終わったと言える基準になります。 |
| **質問** | エージェントがあなたに求める判断。多くは選択肢と推奨を添えます。 | エージェントを止めて待たせます。 |
| **依頼** | あなたがエージェントに向けて書くメッセージ。 | 新しい仕事をエージェントに渡します。 |
| **履歴** | 起きたことを時系列に並べたもの。各項目は日時と理由を持ちます。 | 新しいセッションや別のエージェントが、前の続きから始められるようにします。 |
| **下書き** | 自分がブラウザで書いている途中のタスクやエピック。 | エージェントが作業に取りかからないようにします。 |
| **バックログ** | まだ始めてはいけない確定済みの計画を置くレーン。 | 「始めない」という意味です。エージェントは始めず、未着手へ送れるのは人だけです。 |
| **アーカイブ** | 片付けたタスク。 | 書き込みをすべて止めます。 |

タスクには、計画・結果・リンクを書く自由なMarkdownの**タイトル**と**本文**もあります。タスクは最大で一つのエピックに所属します。エピックの進行順と、列の中での並びは別のものです。

すべては、あなたのマシンのフォルダ（既定では`~/.agent-project/`）に通常のファイルとして保存されます。ブラウザ、`agpj`コマンド、エージェントが同じファイルを読み書きします。[データとバックアップ](./operations/data)を参照してください。

## 状態

タスクは三つの**列**のどれかにあります。**未着手**（Todo）はまだ始めていない作業、**進行中**（Doing）は作業中、**完了**（Done）は終わった作業です。進行中のAI担当タスクには、エージェントが何をしているかを示す**未稼働**（Idle）・**稼働中**（Running）・**稼働待**（Paused）も表示されます。

| 担当 | 未着手 | 進行中 | 完了 |
| --- | --- | --- | --- |
| **AI** | 未稼働 | 未稼働、稼働中、稼働待 | 未稼働 |
| **ユーザー** | 未稼働 | 未稼働 | 未稼働 |

- **未稼働**は、エージェントがそのタスクに取り組んでいないことを表します。
- **稼働中**は、エージェントが最後に報告した状態で、進行中のAI担当タスクにだけ付きます。生存確認ではないので、エージェントが落ちても、誰かが変えるまでそのタスクは稼働中のままです。
- **稼働待**は、進行中にあって、稼働が止まっているタスクを表します。稼働中のエージェントが質問を出したとき（下記）、常駐エージェントがエラーで止まったとき、あなたが一時停止したとき、止まりを指摘されたエージェントが作業していないタスクを一時停止したときに稼働待になります。
- 進行中では、状態の変更は、未稼働から稼働中、稼働中から稼働待、稼働待から稼働中の3つだけで、それ以外は拒まれます。
- **回答待**（Awaiting answer）は状態ではなく、誰も設定できません。質問から導かれる印で、担当者や列を問わず、未回答の質問を参照しているタスクに表示されます。回答待は稼働状態のラベルに代わって表示され、進行中でないタスクは、それ以外では稼働状態のラベルを表示しません。
- 進行中に移すときと、進行中から別の列へ移すときは、状態が未稼働に戻ります。進行中に移したタスクは未稼働から始まります。進行中の中で並べ替えるだけなら状態は保たれます。列を移しても、未回答の質問は残ります。
- あなたが担当のタスクは、常に未稼働です。

## 質問 {#decisions}

エージェントはあなたの判断なしには進めないとき、**質問**を出します。たいていは選択肢と推奨が付きます。質問はプロジェクトに属し、それを参照するタスクが**回答待**と表示され、質問を示します。選択肢を選ぶか、メモを書くか、両方を行って回答すると、回答は履歴に残り、エージェントはそれを読んでから作業を再開します。質問は、回答されるまで未回答のまま残ります。

回答は、カンバン、スマホ、チャット、CLIのどこからでもできます。最初に記録された回答が有効です。答え方は[判断依頼](./delegate/decisions)で説明します。

## 完了条件と自動完了

完了条件は、作業を始める前に書きます。エージェントは、検証が済んだ条件だけを達成済みにします。AI担当のタスクのすべての条件が達成で、あなたを待つものがなくなると、サーバーが動いている間、タスクは自動で**完了**に移り、その理由が履歴に残ります。条件のないタスク、あなたが担当のタスク、下書き、回答待のタスクは、自動では完了しません。完了したタスクの状態は未稼働です。ファイルの形式は[Markdownファイルの形式](./reference/file-format)に説明があります。

## エピックと作業の順序

エピックは、タスクをまとめて管理する単位です。名前・色・Markdownで書いた詳細・タスクの順序を持ちます。エージェントは順序を読んで、次にやることを選びます。[エピックと進行表](./watch/epics)を参照してください。

## 履歴

タスクの移動や状態変更、質問と回答、チェックした条件、エージェントが追記した進捗のメモが、履歴に記録されます。各項目は日時と理由で構成され、履歴は記録のように読めます。エージェントは、やったことと確かめたことも書き残します。**履歴**タブでは新しい順に確認できます。

## Agent Projectが保証すること

次の決まりは、エージェントの善意ではなく、Agent Projectそのものが守ります。

- **タスクの担当は変わりません。** 担当は作成時に決まります。
- **有効な状態だけが存在します。** 組み合わせられない列と稼働状態は拒まれ、列に合わない状態は手で設定できず、進行中で許されるのは、未稼働から稼働中、稼働中から稼働待、稼働待から稼働中の変更だけです。
- **回答がなければ、エージェントは待ちます。** 未回答の質問を参照するタスクは回答待と表示され、エージェントは稼働中にできません。進行中で稼働中のタスクについて質問を出す（または質問に結び付ける）と、そのタスクは同時に稼働待になり、履歴に「Q-1 の回答を待ちます。」と記録されます。エージェントが回答を受け取ると、タスクは自動で稼働中に戻り、履歴に「Q-1 の回答を受け取ったので再開しました。」と記録されます。エージェントは、進行中のタスクを未着手に戻すこともできません。戻せるのはあなただけです。
- **回答は一度だけ記録されます。** 最初の回答が有効で、上書きされません。質問・回答・それを参照するタスクの履歴は、まとめて保存されます。
- **完了は、条件を満たしたことを意味します。** AI担当のタスクが完了するには、完了条件が1つ以上あり、すべて達成され、未回答の質問がないことが必要です。移すときには、最新のファイルで確かめ直し、理由を履歴に残します。これは自動の完了が確かめる条件です。エージェントが手で完了に移すときも、すべての条件の達成と未回答の質問がないことが必要ですが、完了条件のないタスクは拒まれません（[まだエージェント頼みのところ](#relies-on-agent)を参照）。
- **終わった仕事は、終わったままです。** エージェントは完了したタスクを変更できません。あなたが列を戻せば、再び作業できます。条件のチェックを外しても、完了したタスクは自動では戻りません。
- **下書きとアーカイブは守られます。** エージェントはあなたの下書きに触れられず、アーカイブしたタスクには誰も書き込めません。
- **すべてに理由が残ります。** 列・状態・質問・回答・条件のチェックの変更は、理由とともに履歴に記録されます。タスクと質問の番号は使い回されません。
- **壊れた記録は推測で補いません。** 形の崩れた履歴は、読み替えずにエラーとして扱います。
- **計画を書き換えても、記録は残ります。** タスクの本文と条件を置き換えても、履歴と質問への参照は保たれます。

## 介入するところ

関わり方は二つあり、どちらも同じ仕事のモデルを通ります。

| 関わり方 | 起きること | あなたがすること |
| --- | --- | --- |
| **聞かれたら答える**（Human-in-the-Loop） | エージェントが、自分では決められない判断のために止まって待ちます。 | 作業中にエージェントが尋ねる質問に答える。 |
| **見守って介入する**（Human-on-the-Loop） | あなたが見ている間も、エージェントは動き続けます。次にプロジェクトの情報を読むときに、変更に従います。 | カードを戻す、または完了にする、条件にチェックを付ける、本文や条件を書き換える、アーカイブする、削除する。 |

エージェントがあなたを呼ぶのは、意図が分からないとき、好みで決まるとき、取り消せない操作をするとき、頼まれた範囲を超えるときの4つだけです。この線引きはエージェントのSkillにあります。Agent Projectは、未回答の質問があるタスクを稼働中にさせませんが、エージェントのほかの操作までは止めません。エージェントが止まるのは、Skillに従うからです。[エージェントとの連携](./delegate/agents)を参照してください。

## まだエージェント頼みのところ {#relies-on-agent}

Agent Projectがまだ強制していないことがあります。エージェントがSkillに従うことに頼っているので、どこにあるかを知っておいてください。

- **条件のないタスク。** エージェントは、完了条件のないタスクを手で完了に移せます。自動の完了では起きません。
- **誰が答えたか。** Agent Projectは、実際に誰が回答を入力したかを確かめません。チャットで返答したときは、エージェントがあなたの言葉を回答として記録します。
- **ファイルの直接編集。** `TASK.md`を手で書き換えると、書き込みのチェックと履歴の自動記録を通りません。カンバンかCLIを使ってください。
- **稼働中。** 稼働中は自己申告なので、エージェントが止まっていても、動いているように見えることがあります。
- **自動の完了にはサーバーが必要。** `agpj serve`が動いている間だけ起きるので、終わったタスクがサーバーの起動まで進行中に残ることがあります。
- **あなたが担当のタスク。** 記録はされますが、検証はされません。
- **エピック。** エピックが終わったかどうかはAgent Projectが管理せず、完了の条件は本文に書きます。

## ほかの手法・道具とAgent Projectの強み {#compare}

Agent Projectは、エージェントの仕事を実行して追跡する場（ハーネス）です。次のような手法や道具と並べて語られます。

- [AI-DLC](https://aws.amazon.com/blogs/devops/ai-driven-development-life-cycle/)：AWSが提唱する手法。AIが計画・コード・テストの案を作り、人が各段階を確認します。
- [GitHub Spec Kit](https://github.com/github/spec-kit)や[Kiro](https://kiro.dev/docs/specs/)による仕様駆動開発：コードの前に仕様を書き、それを正とします。
- [Vercel Board](https://vercel.com/blog/introducing-vercel-board)：チームの人とコーディングエージェントが仕事を共有する、実験的なメッセージボード。
- [Backlog.md](https://github.com/MrLesk/Backlog.md)：Gitリポジトリ向けの、Markdownで管理するタスク管理とカンバン。

これらの手法はAgent Projectと組み合わせられます。仕様や段階ごとの計画をエピックに置き、各ステップをタスクにできます。

### Agent Projectの強み

- **完了は、先に決めた条件で決まります。** すべての完了条件を達成し、未回答の質問がないときだけ、タスクが完了します。
- **エージェントはあなたに尋ねて待ちます。** カンバンで質問し、回答があるまで止まり、回答後は自分で再開します。スマホからも答えられます。
- **エージェントを止めずに、見守って介入できます。** 状態が変わる様子を見ながら、作業中でもカードを動かし、条件にチェックを付け、計画を書き換えられます。
- **別のセッションやエージェントが続きを引き継げます。** タスクごとに、何をなぜしたかの履歴が残ります。
- **ローカルのファイルで、どのエージェントでも。** データは手元のファイルにあり、`agpj`を実行できるエージェントなら使えます。プラグインはClaude CodeとCodexに対応しています。
